# خطة التطوير الشاملة لمنظومة عُمْرَان (OMRAN)

خطة تنفيذية وهندسية شاملة لترقية منصة عُمْرَان لإدارة المجمعات والحلقات القرآنية: تعزيز الأمان الشامل وقواعد Firestore، تحويل المساعد الذكي إلى وكيل تنفيذي حقيقي بصلاحيات منضبطة وجداول ورسوم تفاعلية وتصدير Excel/PDF، توحيد هوية Duolingo مع لوحة تخصيص ألوان المجمعات، وضبط معمارية النشر الهجين لـ GitHub Pages.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> تم تأكيد القرارات التأسيسية الثلاثة التالية بناءً على إجاباتك:
> 1. **معمارية النشر لـ GitHub Pages**: اعتماد وضع ثنائي هجين (Static SPA جاهز للاستضافة الثابتة مع إمكانية الربط السلس بخادم API خارجي أو العمل بالوضع المدمج محلياً).
> 2. **ترقية المصادقة**: ترقية آمنة للحسابات الحالية إلى Firebase Authentication مع الحفاظ التام على البيانات والربط التلقائي عبر البريد/المعرف بدون فقدان أي سجل.
> 3. **مستوى تفويض المساعد الذكي**: تنفيذ فوري ومباشر للأوامر الآمنة الواضحة (مثل استعلامات الجداول، الإحصائيات، تسجيل حضور طالب محدد)، مع اشتراط بطاقة تأكيد صريحة ومفصلة للأوامر الجماعية أو الإجراءات الحساسة والتدميرية (مثل الحذف أو التعديل الواسع).

- **القرار المعتمد 1 (الأمان وعزل البيانات)**: عزل بيانات كل مجمع قرآني على مستوى قواعد Firestore وتحقق الخادم، مع منع أي تجاوز عبر المتصفح أو تزييف الهوية.
- **القرار المعتمد 2 (أدوات المساعد التنفيذي)**: تزويد المساعد بطبقة أدوات موثوقة (Function Calling / Structured Tool Dispatcher) تنفذ العمليات الحقيقية عبر خدمات النظام وتتحقق من صلاحية المستخدم الحالية قبل أي تعديل.
- **القرار المعتمد 3 (محرك التصدير)**: توليد ملفات Excel حقيقية (.xlsx) بتنسيق عربي كامل وملفات PDF احترافية بهوية المجمع وعُمْرَان مع خيار الحفظ المباشر في مكتبة المنصة.

### 1. Overview & Core Concept

- **طبيعة النظام**: منظومة عُمْرَان منصة متكاملة وذكية لإدارة المجمعات والحلقات القرآنية، تخدم 5 أدوار رئيسية (المطور/مدير النظام الأعلى، المشرف العام، المعلم، الطالب، ولي الأمر).
- **الهدف المحوري**: تحويل تجربة إدارة الحلقات والتسميع من العمل اليدوي المجزأ إلى منظومة مؤتمتة ذكية، حيث يعمل المساعد الذكي كموظف تنفيذي فوري يفهم سياق الحديث، ويعدل الحضور والتسميع، ويستخرج الجداول والرسوم البيانية، ويصدر التقارير الرسمية بدقة متناهية.
- **القيمة المضافة**:
  - صفر تكرار للبيانات وأمان صارم متعدد المستويات (RBAC).
  - تفاعل باللغة الطبيعية باللغة العربية ينتهي بتعديل فعلي موثق في قاعدة البيانات.
  - هوية بصرية مبهجة ومحفزة مستوحاة من Duolingo مع تحكم لوني كامل لكل مجمع.

### 2. User Experience & Visual Design

#### A. التسلسل التفاعلي للمستخدم (User Flows)
1. **تسجيل الدخول الآمن**: واجهة دخول عصرية تدعم الحسابات الحالية والمطابقة مع Firebase Auth مع جلسات مشفرة تمنع التلاعب عبر URL.
2. **المساعد التنفيذي العائم (Executive AI Co-Pilot)**:
   - نافذة محادثة ذكية متوافقة مع الأجهزة الذكية وشاشات الحواسيب.
   - استقبال الأوامر الطبيعية: *"سجّل أحمد ومحمد غائبين يوم الأربعاء وسلمان متأخر"* $\to$ التعرف على الطلاب والتواريخ وعرض جدول النتائج فوراً.
   - اختيار طريقة العرض تلقائياً: بطاقات إحصائية للأرقام، رسوم بيانية تفاعلية (Recharts) لاتجاهات الحضور والحفظ، وجداول محكمة للتفاصيل.
   - أزرار تصدير فورية أسفل كل جدول/رسم: [تصدير Excel 📊] و [تصدير PDF 📄] و [حفظ بالمكتبة 💾].
3. **لوحة تخصيص ألوان وثيم المجمع**:
   - أداة متطورة لاختيار الألوان (Hex, RGB, Palettes, Eyedropper للقطارة في المتصفحات المدعومة).
   - معاينة فورية ناعمة (Live Preview) مع فحص التباين التلقائي (WCAG Contrast Warning) لضمان وضوح النصوص.
   - حفظ التخصيص في وثيقة المجمع السحابية واستعادته الدائمة.

#### B. الهوية البصرية ونظام الألوان (Duolingo Tactile System)
- **الجو العام**: تفاعلي، مشجع، حيوي، وودود مع أزرار ثلاثية الأبعاد بارزة ذات حواف ملموسة (Tactile 3D Buttons & Cards).
- **توزيع الألوان (60-30-10)**:
  - 60% الخلفية الأساسية: كحلي داكن عميق `#131f24` (أو وضع مخصص حسب إعدادات المجمع).
  - 30% الأسطح الهيكلية والبطاقات: كحلي بترولي `#203843` مع حواف تحديد محكمة `#2b4550`.
  - 10% ألوان التأكيد والتفاعل: ذهبي أصفر دوولينجو `#ffc800` مع ظل سفلي `#e5a500`، وأخضر إنجاز `#58cc02`، وأزرق معلومات `#1cb0f6`، وأحمر تنبيه `#ff4b4b`.
- **الطباعة**: خطوط عربية واضحة ومقروءة (Tajawal للعناوين وواجهات النظام، Amiri للآيات الكريمة والقرآنية، وأرقام جدولية أحادية Tabular Figures للإحصائيات والتواريخ).

### 3. Key Product Decisions & Trade-Offs

- **القرار الأول: معمارية تنفيذ أوامر المساعد الذكي**:
  - *الخيار المعتمد*: طبقة خدمات تنفيذية موثقة (Command Execution Engine) تعمل كواجهة وسيطة تتحقق من الدور والمجمع والطالب في قاعدة البيانات وتنفذ العمليات عبر دوال معتمدة، بدلاً من إعطاء الذكاء الاصطناعي صلاحية كتابة استعلامات مباشرة أو كود تنفيذي غير مقيد.
  - *السبب*: منع أي هجمات حقن أو تعديل غير مصرح به وحماية خصوصية بيانات الطلاب.
- **القرار الثاني: دعم النشر على GitHub Pages**:
  - *الخيار المعتمد*: ضبط Vite بمسار نسبي ديناميكي (`base: './'`)، وفصل مسارات API إلى محول مرن (API Client Adapter) يستطيع التوجيه لخادم Express المرفوع على Cloud Run / Node، مع وضع وضع تشغيل ذاتي آمن إذا كانت الخدمة ثابتة.
  - *السبب*: تمكين المستودع من البناء والنشر التلقائي على GitHub Pages دون كسر مسارات الأصول (`assets`) أو مسارات SPA.
- **القرار الثالث: دعم التصدير العربي إلى Excel و PDF**:
  - *الخيار المعتمد*: استخدام مكتبات إنشاء وتنسيق الجداول العربية مع تضمين الرسوم البيانية وملخص المجمع وهوية المنصة، وربط مخرجاتها بمكتبة المنصة الرقمية بصلاحيات المجمع.

#### الكيانات وسجل البيانات الأساسي:
- **المستخدمون والحسابات (`users` / `teachers` / `admins`)**: إدارة دقيقة بالمعرفات الحقيقية، وإلغاء أي كلمات مرور ثابتة.
- **المجمعات والحلقات (`complexes` / `halaqahs`)**: عزل كامل للسجلات.
- **الطلاب والحضور (`students` / `attendance`)**: دعم حالات الحضور الكاملة (حاضر، غائب، متأخر، معتذر، مستأذن) مع فهارس تمنع الازدواجية.
- **التقييمات والتسميع (`evaluations`)**: حفظ دقيق لما تم تسميعه (جديد، مراجعة صغرى، مراجعة كبرى) ودرجات المعايير.
- **المكتبة والملفات المصدرة (`library`)**: تخزين التقارير وتحديد مستويات الوصول لها.

#### مراحل التنفيذ الهندسية:
1. **المرحلة 1: الأمان الصارم والمصادقة**:
   - إزالة أي كلمات مرور ثابتة وفحص جميع مسارات التسجيل.
   - تشديد `firestore.rules` وتطبيق تدقيق المجمع والأدوار.
   - حماية مسارات بوابة ولي الأمر باستخدام رموز وصول آمنة غير قابلة للتخمين.
2. **المرحلة 2: محرك المساعد التنفيذي الذكي**:
   - بناء طبقة الأدوات (`OmranExecutiveAgentTools`) لتنفيذ القراءة، التعديل الفردي والجماعي للحضور والتسميع، ونقل الطلاب، واستخراج الإحصائيات.
   - تفعيل المحادثة متعددة الجولات مع الحفاظ على سياق الطلاب والتواريخ.
   - دعم الجداول التفاعلية والرسوم البيانية (Recharts) داخل واجهة الشات.
3. **المرحلة 3: التصدير والمكتبة (Excel & PDF)**:
   - تصدير الجداول المعروضة إلى مصنفات Excel (.xlsx) تدعم اللغة العربية واتجاه اليمين إلى اليسار.
   - توليد وثائق PDF منسقة وربط الملفات بمكتبة المجمع.
4. **المرحلة 4: توحيد ثيم Duolingo وتطوير منتقي الألوان**:
   - توحيد متغيرات CSS لجميع المكونات دون استثناء.
   - بناء لوحة ألوان تفاعلية تتضمن Color Picker و HEX/RGB ومقترحات التباين وأداة القطارة مع حفظ التغييرات لكل مجمع.
5. **المرحلة 5: تهيئة النشر على GitHub Pages واختبارات الجودة**:
   - ضبط `vite.config.ts` وتهيئات البناء ومسارات SPA وإعداد سير عمل GitHub Actions.
   - تنفيذ اختبارات شاملة تغطي البناء، الأمان، سيناريوهات المساعد الذكي، والتصميم.
